Tutorial 2: shortest paths

GR4 (Tutorial 2 warm-up). π(s,t) is a shortest path in an undirected graph with positive weights. Is it still shortest if (1) every weight is multiplied by c>0? (2) every weight is increased by c>0?

Solution

Solution. (1) Yes. Scaling changes neither V nor E, so the competing s–t paths are the same objects, and w′(P)=cw(P) for every path. For any path Q, w(π)≤w(Q), and multiplying by c>0 keeps the direction: w′(π)≤w′(Q). So π is still shortest and δ′=cδ. (For c<0 the inequality would reverse: the hypothesis is used.)

(2) No. Now w′(Q)=w(Q)+c∣Q∣: the shift grows with the number of edges, so it is not common to all competitors. Counterexample: s−a−t with weights 1, 1 and a direct edge s−t of weight 3. Originally sat costs 2<3. With c=2: sat costs 3+3=6 and st costs 5, so the direct edge is now the unique shortest path. (If all s–t paths had the same number of edges, the answer would be yes again.)

GR5 (Tutorial 2, BFS and Dijkstra share one proof). Show BFS computes shortest paths for unit weights by proving its queue invariant, and give the example where Dijkstra fails with a negative edge.

Solution

Solution. Invariant: if the queue is ⟨v1​,…,vr​⟩ front to back, then d[v1​]≤⋯≤d[vr​]≤d[v1​]+1. It holds for ⟨s⟩. Popping v1​ pushes each newly seen neighbour x with d[x]=d[v1​]+1, which is ≥d[vr​] (order kept) and ≤d[v2​]+1 (bound kept). So the front always has a minimum key: BFS is Dijkstra with a FIFO queue instead of a heap, and Dijkstra's correctness proof applies. Cost O(∣V∣+∣E∣).

Negative edge: s→u (1), s→v (2), v→u (−2). Dijkstra finalises u with d[u]=1 before looking at v, but δ(u)=2−2=0. Dijkstra's proof uses w≥0 in exactly one place: δ(y)≤δ(u) for a vertex y before u on a shortest path.

GR6 (Tutorial 2, preferred directions: 0-1 BFS). n cities, m two-way roads, each with a preferred direction; driving against it is one violation. Find the fewest violations on a route from s to t (n,m≤106).

Solution

Solution. Reduction. For a road u−v preferred u→v, add directed edges u→v of weight 0 and v→u of weight 1. A route s=c0​,…,cL​=t is exactly a walk in G′, and its number of violations is the walk's weight, so the answer is δG′​(s,t) (walks and paths give the same minimum since w≥0). t is reachable iff it is in the underlying graph.

0-1 BFS. Run Dijkstra with a deque instead of a heap: after a successful relaxation along a weight-0 edge push to the front, along a weight-1 edge push to the back; always pop the front, skipping vertices already done.

Invariant: deque keys k1​≤k2​≤⋯≤kr​≤k1​+1. Popping the front key m (which equals dist[u] for a not-yet-done u): a 0-edge pushes key m to the front, at most every surviving key; a 1-edge pushes m+1 to the back, at least every surviving key. Both preserve sorted order and the "within 1" bound. So pop_front returns a minimum key, and Dijkstra's proof applies unchanged.

Cost: each vertex is finalised once, each edge relaxed once, each push popped once, O(1) each: O(n+m), against O(mlogn) with a heap.

Tutorial 2: MSTs

GR7 (Tutorial 2, Kruskal and union–find). How does Kruskal detect cycles quickly?

Solution

Solution. Keep a disjoint-set union of the components of the forest built so far. Adding edge (u,v) creates a cycle iff find(u)=find(v); otherwise add it and union(u,v). Union by rank keeps trees O(logn) tall, and path compression (pointing every vertex on a find path straight at the root) makes them almost flat, so a sequence of operations costs nearly O(1) each (inverse Ackermann). Kruskal is then dominated by sorting: O(mlogm)=O(mlogn).

GR8 (Tutorial 2, updating an MST when one weight changes). T is an MST of G; edge e changes weight from w(e) to w^(e). Update T in O(∣V∣+∣E∣) in all four cases.

Solution

Solution.

  • (a) e∈/T, heavier. Keep T. e was the heaviest edge of the cycle it closes in T∪{e} (else swapping would improve T); it is still the heaviest, so by the cycle property it stays out. O(1).
  • (c) e∈T, lighter. Keep T. Its weight drops by Δ; every spanning tree containing e drops by Δ and every other tree is unchanged, so T is still minimum. O(1).
  • (b) e=(u,v)∈/T, lighter. T∪{e} has a unique cycle C: find the u–v path in T by DFS, O(∣V∣). Let emax​ be the heaviest edge of C. If w^(e)<w(emax​), set T′=T∪{e}∖{emax​}, else T′=T. By the cycle property the heaviest edge of C is in no MST, and no other cycle has gained a lighter edge.
  • (d) e∈T, heavier. Removing e splits T into two parts, giving a cut (S,V∖S); find S by DFS in O(∣V∣). Scan all edges for the lightest edge emin​ crossing the cut (with e at its new weight), O(∣E∣). Set T′=T∖{e}∪{emin​}. The two halves of T are still optimal inside, and by the cut property the lightest crossing edge belongs to an MST.

GR9 (Tutorial 2, water supply). N houses; a well at house i costs Wi​, a pipe between i and j costs Pij​. Every house must get water from its own well or through pipes from a house with a well. Minimise the cost.

Solution

Solution. Construction. Add a dummy vertex 0 (the water table); for each house an edge 0−i of weight Wi​, and for each pipe an edge i−j of weight Pij​. Answer: the MST of G′ on N+1 vertices (Prim from vertex 0).

Correctness. Take an optimal configuration. In each pipe-connected group, the pipes form a tree (a cycle would have a removable pipe) and there is exactly one well (none means no water; two means one well can be dropped). Groups plus their well edges to 0 form a connected acyclic spanning subgraph of G′: a spanning tree of the same cost. Conversely, in any spanning tree of G′, deleting vertex 0 splits the houses into groups, each attached to 0 by exactly one well edge and internally connected by pipes, which is a valid configuration of the same cost. So optimal cost = MST weight. Time O((N+M)logN) with M pipes.

GR10 (Tutorial 2, free swaps and paid swaps). An array A of distinct integers; M "VIP" index pairs can be swapped any number of times for free, and other adjacent pairs (i,j) can be made swappable for a one-time cost Cij​. (1) What is the lexicographically largest array using only free swaps? (2) What is the cheapest set of paid swaps after which every permutation is reachable?

Solution

Solution. (1) Swaps along a connected set of index pairs generate every permutation of that set's positions (adjacent transpositions along a spanning tree generate the symmetric group). So: union–find over the VIP pairs; for each component, sort its indices ascending and its values descending and place them in that order. Within each component, the largest values go to the earliest positions, which is lexicographically best, and no value can leave its component.

(2) Every permutation is reachable iff the "swap graph" on indices is connected. Treat each free component as one super-vertex and run Kruskal on the paid swaps, starting from the union–find of part (1): add a paid swap only if it joins two different components. This is an MST of the contracted graph, which is the cheapest way to connect it (cut property).

GR11 (Tutorial 2, XOR MST). N≤105 numbers; joining i and j costs A[i]⊕A[j]. Find the MST without building all Θ(N2) edges.

Solution

Solution. Split by the highest bit. Let b be the highest bit where not all numbers agree; split the numbers into L (bit b = 0) and H (bit b = 1). Every edge inside L or inside H has bit b = 0 in its XOR (and all higher bits 0), while every cross edge has bit b = 1, so every cross edge is heavier than every inside edge. Hence (cycle and cut properties) the MST is: an MST of L, an MST of H, and exactly one cross edge, the cheapest one (the cut (L,H) must be crossed, and by the cut property its lightest edge is in the MST; a second cross edge would close a cycle in which it is heaviest). Recurse on L and H.

The cheapest cross edge: insert L into a binary trie, and for each y∈H walk the trie greedily choosing the child that matches y's next bit; this finds minx∈L​x⊕y in O(B) for B-bit numbers. Each number is handled once per level of the recursion, so the total is O(NB2) (or O(NB) with care), versus Θ(N2) for Prim on the complete graph.

Assigned DPV exercises: chapter 3 (exploring graphs)

GR12 (DPV 3.7, bipartite graphs). (a) Give a linear-time test for bipartiteness. (b) Prove that a graph is bipartite iff it has no odd cycle. (c) How many colours does a graph need if it has exactly one odd cycle?

Solution

Solution. (a) BFS (or DFS) from each unvisited vertex, colouring each newly reached vertex opposite to its parent; the graph is bipartite iff no edge joins two vertices of the same colour. O(n+m).

(b) (⇒) Along any cycle the sides alternate, so returning to the start needs an even length. (⇐) In a connected graph with no odd cycle, colour v by the parity of its BFS distance d(v) from a root. An edge uv has ∣d(u)−d(v)∣≤1; if d(u)=d(v), the two BFS paths to u and v plus the edge uv contain a cycle of odd length 2d(u)−2d(w)+1, where w is where the paths split. So every edge joins different parities.

(c) 3. Delete one edge e=xy of the odd cycle; the rest has no odd cycle, so it is 2-colourable. If x and y got the same colour, recolour x with a third colour (its other neighbours are 2-coloured, so this is safe). At least 3 are needed because an odd cycle is not 2-colourable.

GR13 (DPV 3.8, pouring water). Containers of 10, 7 and 4 pints; the 7 and 4 start full and the 10 empty. Pouring stops when the source empties or the target fills. Can exactly 2 pints end up in the 7- or 4-pint container? Model it as a graph problem.

Solution

Solution. Graph: a vertex for each state (a,b,c) (contents of the 10, 7, 4) with a+b+c=11; a directed edge for each legal pour. The question is reachability from (0,7,4) to any state with b=2 or c=2: run BFS (or DFS). Yes, and BFS finds the shortest sequence:

(0,7,4)→(4,7,0)→(10,1,0)→(6,1,4)→(6,5,0)→(2,5,4)→(2,7,2).

(Pour 4→10, 7→10, 10→4, 4→7, 10→4, 4→7: the 4-pint container ends with 2.)

GR14 (DPV 3.16, prerequisites). Courses with prerequisite edges form a DAG. With unlimited courses per semester, find the fewest semesters needed.

Solution

Solution. A course can be taken in semester $1 + $ (longest chain of prerequisites ending at it). Compute L(v)=1+max(u,v)​L(u) (with L(v)=1 for sources) in topological order: a longest-path DP on the DAG, O(n+m). The answer is maxv​L(v): taking each course in semester L(v) is legal, and a chain of k courses forces at least k semesters.

GR15 (DPV 3.26, Euler tours). (a) A connected undirected graph has a closed walk using every edge exactly once iff every degree is even. (b) It has an Euler path (not closed) iff exactly 0 or 2 vertices have odd degree. (c) Directed version?

Solution

Solution. (a) (⇒) Each pass through a vertex uses one edge in and one out, so degrees are even. (⇐) Walk from v along unused edges; with all degrees even, you can only get stuck at v, so you trace a closed walk. If edges remain, some vertex on the walk has unused edges (connectivity); start a new closed walk there and splice it in. Repeat (Hierholzer, O(m)). (b) With two odd vertices x,y, add an edge xy, take the Euler tour, delete the added edge: an Euler path from x to y. Conversely, an open Euler path makes exactly its two endpoints odd. (c) Directed: an Euler tour exists iff the graph is (strongly) connected on its non-isolated vertices and in(v)=out(v) for every v.

GR16 (DPV 3.28, 2-SAT). Give a linear-time algorithm for 2-SAT.

Solution

Solution. Implication graph: vertices xi​ and ¬xi​; each clause (a∨b) gives edges ¬a→b and ¬b→a (if a is false, b must be true). Claim: Φ is unsatisfiable iff some xi​ and ¬xi​ lie in the same SCC. (If they do, xi​⇒¬xi​⇒xi​, impossible.) Otherwise, process SCCs in reverse topological order (sinks first) and set every literal in an unassigned SCC to true and its complement to false; this never makes an implication true⇒false. SCCs take O(n+m). So 2-SAT is in P, unlike 3-SAT.

Assigned DPV exercises: chapters 4 and 5 (paths and MSTs)

GR17 (DPV 4.5, counting shortest paths). In an unweighted graph, count the shortest s–v paths for every v in linear time.

Solution

Solution. BFS from s with cnt[s]=1. When scanning edge (u,v): if v is new, set d[v]=d[u]+1 and cnt[v]=cnt[u]; else if d[v]=d[u]+1, add cnt[u] to cnt[v]. A shortest path to v ends with an edge from some u with d[u]=d[v]−1, and all such u are finished (dequeued) before v is, so the counts are complete. O(n+m).

GR18 (DPV 4.10, at most k edges). Shortest paths from s using at most k edges, negative weights allowed.

Solution

Solution. Run k rounds of Bellman–Ford, each relaxing every edge using the values from the previous round (keep two arrays). By induction, after round i, d[v] = the lightest s–v walk with at most i edges. O(km).

GR19 (DPV 4.13, fuel range). Cities and highways with lengths ℓe​; a car can drive at most L between refuelling stops (cities). (a) Decide in linear time whether s can reach t. (b) Find the smallest tank range that allows the trip in O((n+m)logn).

Solution

Solution. (a) Delete every edge with ℓe​>L and test reachability by BFS/DFS: O(n+m). (b) We need the path minimising its longest edge (a minimax or bottleneck path). Modify Dijkstra: d[s]=0, relax d[v]←min(d[v],max(d[u],ℓuv​)). The same proof works because max(d[u],ℓ) never decreases along a path, just like sums with non-negative weights. O((n+m)logn). (Equivalently: the path between s and t in an MST minimises the largest edge.)

GR20 (DPV 4.17, small integer weights). All weights are integers in {1,…,W}. Run Dijkstra in (a) O(W∣V∣+∣E∣) and (b) O((∣V∣+∣E∣)logW).

Solution

Solution. (a) Distances are at most W(∣V∣−1). Use an array of buckets indexed by distance; insert/decrease-key moves a vertex between buckets in O(1); deletemin scans forward from the last nonempty bucket, and the scan pointer only moves forward (Dijkstra extracts in nondecreasing order), so total scanning is O(W∣V∣). (b) At any moment the keys in the queue lie in a window [D,D+W] (every key is the last extracted distance plus at most W), so only W+1 distinct key values are live: keep a heap over the at most W+1 nonempty buckets, so each operation is O(logW).

GR21 (DPV 4.21, currency exchange). Rates rij​ (one unit of i buys rij​ of j). (a) Find the most profitable conversion sequence from s to t. (b) Detect an arbitrage opportunity (a cycle with product of rates >1).

Solution

Solution. Use weights wij​=−logrij​. A product of rates is maximised exactly when the sum of −log is minimised, and ∏r>1⟺∑(−logr)<0. (a) Bellman–Ford from s (weights can be negative), O(nm), assuming no arbitrage. (b) Run one more round: any further improvement means a negative cycle, which is an arbitrage. The Lecture 12 "opportunity cycle" problem is exactly (b).

GR22 (DPV 4.22, best ratio cycle). Each city j has profit pj​, each edge cost cij​>0; find a cycle maximising ∑c∑p​. (a) For a given r, test whether some cycle has ratio >r. (b) Find the best ratio to within ε.

Solution

Solution. (a) Weight each edge wij​=rcij​−pj​. A cycle C has ratio >r ⟺∑C​pj​>r∑C​cij​⟺∑C​wij​<0. So run Bellman–Ford negative-cycle detection, O(nm). (b) The ratio lies in [0,R] with R=∑p/minc; binary search on r with test (a), O(log(R/ε)) times.

GR23 (DPV 5.5, adding 1 to every weight). (a) Does the MST change? (b) Do shortest paths change?

Solution

Solution. (a) No. Every spanning tree has exactly n−1 edges, so every tree's weight rises by n−1 and their order is unchanged. (b) Yes, possibly: paths with more edges gain more (GR4(2)).

GR24 (DPV 5.9, true or false about MSTs). Decide each statement for a connected undirected weighted graph.

Solution

Solution.

Statement Answer and reason
If G has more than n−1 edges and a unique heaviest edge, that edge is in no MST. False: a heaviest edge that is a bridge must be in every spanning tree.
If G has a cycle with a unique heaviest edge e, then e is in no MST. True: cycle property (swap e for a lighter cycle edge across the cut it defines).
Let e be any edge of minimum weight. Then e is in some MST. True: cut property on any cut that e crosses.
If the lightest edge is unique, it is in every MST. True: if an MST T lacked e, then T∪{e} has a cycle whose other edges are all heavier than e; removing one gives a strictly lighter spanning tree.
If G has a cycle with a unique lightest edge e, then e is in every MST. False: triangle a,b,c with ab=5, bc=6, ca=7, plus a vertex x joined to a and b with weight 1 each. ab is the unique lightest edge of the cycle abc, but it is the heaviest edge of the cycle axb, so it is in no MST.
Dijkstra's shortest-path tree is an MST. False: triangle s–a 2, s–b 2, a–b 1: SPT uses both 2s (weight 4), MST weight 3.
The shortest path between two vertices is part of some MST. False: sa=3, sb=2, ab=2. The shortest s–a path is the direct edge (3 < 4), but the only MST is {sb,ab} (weight 4), which does not contain it.
Prim's algorithm works with negative weights. True: the cut property never uses the sign of the weights.
