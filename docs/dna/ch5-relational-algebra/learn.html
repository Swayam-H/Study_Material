Relational algebra

8 min read

Relational algebra (RA) is a small set of operations that take relations and return a relation. Every SQL query is translated into an RA expression before it runs, and this course tests RA directly: Assignment 5 asked for three RA queries (individual) and a proof plus three queries (group) on a BOOKS database. Sources: Elmasri and Navathe 7e sections 8.1–8.5; Kamal's practice exercises 8.15–8.17 and 8.22; Assignment 5 keys and rubrics; past-paper outer-join questions.

Study path. Learn the operations in the order below and do Practice A (the real A5 questions) on paper. Most RA questions are one of five patterns: select–join–project, set difference for "no" or "not all", self-join for comparing two rows, division for "every", and grouping for counts. The pattern list in the Reference is the fastest revision.

The notation

Selection σc​(R) Rows of R satisfying condition c
Projection πL​(R) Columns L of R, duplicates removed

Union, intersection, difference R∪S, R∩S, R−S Set operations; R and S must be union-compatible
Cartesian product R×S Every row of R paired with every row of S
Theta join R⋈c​S σc​(R×S)
Equijoin R⋈A=B​S Theta join with only = conditions; both A and B kept
Natural join R∗S or R⋈S Equijoin on all same-named attributes, one copy kept
Division R÷S Values of R's extra attributes paired with every row of S
Aggregate / grouping γG;F(A)→N​(R), Elmasri: G​FFA​(R) One row per group of G with aggregate values

Assignment T←E Names an intermediate result

Selection σc​(R): c is built from comparisons (=, ≠, <, ≤, >, ≥) of attributes and constants, joined with AND, OR, NOT. It is applied row by row, so it can never compare two different rows (that needs a join). Selection is commutative and cascades: σc1​​(σc2​​(R))=σc1​∧c2​​(R).

Projection πL​(R): keeps the listed columns and removes duplicate rows (relations are sets). This is the main difference from SQL SELECT, which keeps duplicates unless you write DISTINCT. If L contains a key, the number of rows does not change.

Rename ρ: needed to (a) join a relation with itself (self-join), (b) make attribute names match for a natural join or set operation, (c) name results.

Set operations

R and S are union-compatible if they have the same number of attributes and the i-th attributes have the same domain. Then R∪S, R∩S, R−S are defined; the result takes R's attribute names. ∪ and ∩ are commutative and associative; − is neither. R∩S=R−(R−S).

Difference is how RA says "not". "Employees who work on no project" = all employees minus those who work on some project:

πSsn​(EMPLOYEE)−ρ(Ssn)​(πEssn​(WORKS_ON))

Products and joins

R×S pairs every row with every row: |R| × |S| rows, degree deg R + deg S. On its own it is meaningless; followed by a selection it is a join.

Theta join R⋈c​S=σc​(R×S). Equijoin: only equality comparisons; the joined attributes both appear. Natural join R∗S: equality on all attributes with the same name, keeping one copy. If R and S share no attribute names, the natural join is a Cartesian product. If they share all names, it is the intersection (A5 group Q1, proved below). Rows with NULL in a join attribute never match.

The join selectivity is |R ⋈ S| / (|R| × |S|). A join on a foreign key to a key returns at most |R| rows.

Outer joins keep rows that find no partner:

  • Left outer R ⟕ S: every row of R; unmatched ones padded with NULLs in S's attributes.
  • Right outer R ⟖ S: every row of S.
  • Full outer R ⟗ S: both.

Use an outer join whenever the question says "for each X … including those with none": "every department and its employee count, including departments with no employees".

A left outer join can be built from the basic operations (M24 Quiz 4 Q1):

T1​T2​R⟕c​S​←R⋈c​S←R−πattrs(R)​(T1​)=T1​∪(T2​×{(NULL,…,NULL)})​

Division

R(Z)÷S(X) with X ⊆ Z, Y = Z − X: the Y-values y such that for every tuple s in S, (y, s) is in R. "Employees who work on all the projects that John Smith works on":

SMITH_PNOSSSN_PNOSANSWER​←πPno​(WORKS_ON⋈Essn=Ssn​σFname=‘John’∧Lname=‘Smith’​(EMPLOYEE))←πEssn,Pno​(WORKS_ON)←SSN_PNOS÷SMITH_PNOS​

Division from basic operations (know this; exams ask it):

R÷S=πY​(R)−πY​((πY​(R)×S)−R)​

Read it as: all candidates, minus those candidates that are missing some required partner. The middle part (πY​(R)×S)−R lists every (candidate, required) pair that does not occur.

Aggregates and grouping

γG;F1​(A1​)→N1​,…​(R) groups R by the attributes G and computes aggregates COUNT, SUM, AVG, MIN, MAX in each group. With no G, the whole relation is one group. Elmasri writes Dno​FCOUNT Ssn, AVERAGE Salary​(EMPLOYEE).

  • COUNT(A) counts rows where A is not NULL; duplicates in the group are counted unless you project first (A5 key: π the (book, author) pairs before counting so each author counts once).
  • A group exists only if it has at least one row: a department with no employees does not appear in γDno​ of EMPLOYEE. To include it, use an outer join first and COUNT a column from the inner side (counts NULL as 0).
  • To filter on an aggregate (SQL HAVING), apply σ after γ.

Recursive closure and other notes

RA cannot express recursive closure (all supervisees at any depth) in one expression; each level needs another join. SQL handles it with recursive queries (WITH RECURSIVE, Elmasri 7.1.10) or with a loop in a stored procedure (GA6 did a topological sort that way).

Complete set: {σ, π, ∪, ρ, −, ×} can express all the others (R∩S via −, joins via × and σ, division via the formula above).

How to write an RA answer that earns an A

Kamal's A5 keys always: (1) state keys and foreign keys as assumptions; (2) state the reading of any ambiguous word ("younger", "authors of a book", "number of authors"); (3) give a step-by-step derivation with ← and a final single expression; (4) explain each step in a numbered list, including why duplicates or empty groups are handled correctly. The rubric gives marks for the right pattern (difference for "all", union of the two author roles, separate counts), and accepts alternatives that follow from a stated assumption.
